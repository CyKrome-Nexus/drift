# Drift on the phone

The phone app is Expo (`apps/mobile`). Since it carries its own native code, it runs as a
**development build**. Expo Go still opens it, but setting a wallpaper there only shows a toast.

## Running it

```sh
pnpm ios       # expo run:ios — builds, installs on the booted simulator, starts Metro
pnpm android   # expo run:android — same for a running emulator or a USB device
pnpm dev:mobile  # Metro only, for a dev build that's already installed
```

`ios/` and `android/` are generated by `expo prebuild` and are gitignored. Change native
configuration in `app.json` or in the module, never in those folders.

## Setting the wallpaper (`modules/drift-wallpaper`)

A local Expo module, autolinked from `apps/mobile/modules`. The app sends it a JSON spec
(`nativeSpec()` in `src/lib/wallpaper.ts`): the portrait art layers, the drift timing shared with
the in-app preview (`src/lib/motion.ts`), and the frame rate and Low Power settings.

- **Android**: `DriftWallpaperService` is a live wallpaper that draws the art on a hardware
  canvas, at the chosen frame rate, and stops while hidden or in Battery Saver (if "Pause in Low
  Power Mode" is on). The first time, the system preview opens and the user taps "Set wallpaper"
  and picks home, lock or both. Apps can't skip that step. After that, choosing another Drift
  wallpaper switches it in place.
- **iOS**: apps can't set the wallpaper. One tap renders a 3-second Live Photo (an H.264 `.mov`
  and a JPEG that share a content identifier) and saves it to Photos (add-only permission). A
  hint then says what to tap, and Drift opens Photos (`photos-redirect://`, an undocumented
  but long-standing URL). There the user taps the newest photo › Share › Use as Wallpaper.
  Apple offers no link to a specific photo or to the wallpaper screen, so those last taps stay
  with the user. If Photos won't open, Drift shows its own guide to Settings › Wallpaper.
- **iOS, experimental — Shortcut**: Settings › iPhone wallpaper › "Set with Shortcut". The user
  builds a "Drift Wallpaper" shortcut once (Get Latest Photos → Set Wallpaper Photo with Show
  Preview off → Open App Drift; steps are on the setup screen). Drift then saves the photo and
  runs it via `shortcuts://run-shortcut?name=Drift%20Wallpaper` (Apple's documented URL), so the
  wallpaper changes with one tap. If Shortcuts won't open, it falls back to the Photos flow.

## EAS

`apps/mobile/eas.json` has these profiles: `development` (dev client, internal),
`development-simulator`, `preview` (internal; APK on Android) and `production` (store builds,
build numbers increased remotely). Before the first build, the owner has to:

```sh
cd apps/mobile
npx eas-cli@latest login
npx eas-cli@latest init            # creates the expo.dev project, writes extra.eas.projectId
npx eas-cli@latest build --profile development --platform all
npx eas-cli@latest submit --profile production --platform all   # needs store listings
```

Phone releases go through EAS, not through the desktop tag release.

## CI

Every PR bundles the JS for both platforms and compiles the Android native project
(`expo prebuild` + `assembleDebug`, x86_64 only). The iOS native build isn't in CI yet.
